# Domain Docs

For work on Agent Home itself, use the root `GLOSSARY.md` and relevant decisions under `docs/adr/`.

For work in a registered project, follow repository routing first. Read the project's applicable glossary and ADRs, starting with the nearest scope. Read parent glossaries for concepts that apply more broadly and the project's `GLOSSARY-MAP.md` when it exists.

Use the owning scope's vocabulary in issues, proposals, tests, and implementation notes. Follow the glossary's preferred terms. When a needed concept lacks a term, check existing project language first and bring a genuine terminology gap to `domain-modeling`. If a proposal contradicts a relevant ADR, identify the decision and why the proposal reopens it.
